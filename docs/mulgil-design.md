### yc-lecture에서 살릴 것과 버릴 것

**살린다**
- 출처 추적: 인용 칩에서 전사 시각으로 바로 가는 흐름.
- 사실과 해석의 분리(🔥/📘/★/📋 → 이번에는 정한 것/할 것/기다리는 것/미정).
- 모르는 것을 지우지 않고 남기기(❓ 보존).
- 원본 보존.
- 별칭으로 부르기.
- append-only 로그.
- `tools/transcribe.sh`의 반복 루프 방지 옵션과 "고유 문장 20% 미만이면 실패" 자체 점검. 실측(39분 강의에서 같은 문장 2,983회 반복)으로 검증된 노하우다. 단, 실제로 효과를 낸 것은 `--condition-on-previous-text False`와 `--compression-ratio-threshold`다. 같이 적힌 `--hallucination-silence-threshold`는 `--word-timestamps True` 없이는 동작하지 않으므로 한 번도 적용된 적이 없다(§5.1)【레드팀: 현실성 major】.

**버린다**
- 완료 게이트(흡수율 55%, 검증 5종).
- 과목 격리를 저장 구조의 벽으로 둔 것.
- `claude -p` 브리지.
- 서버와 브라우저로 실행하는 방식.
- `~/Downloads`를 전제로 한 수집.
- 데이터가 흐르기 전에 UI부터 다듬은 순서.

## 3. 시스템 개요

```
 [Galaxy]                                 [맥: Mulgil.app — 메뉴바 상주, 단일 프로세스, 서버 없음]
 삼성 음성녹음 ──Syncthing-Fork───┐
 (/Recordings/Voice Recorder)     │ (Wi-Fi, 보내기 전용)
                                  ▼
                      ~/Mulgil/inbox/phone/ (받기 전용 + ignoreDelete)
                                  │ FSEvents        ┌──────────────────────────────────────────────┐
 Zoom/화면녹화/다운로드 ──────────┴───────────────▶│ Ingest → Normalize → VAD → Transcribe → Gate │
                                                    │      ↓ sha·creation_time·mtime−duration      │
                                                    │ Matcher(시간 겹침·시리즈) → L1 규칙 후보      │
 Google Calendar 앱 '#' 이벤트 ─┐                   │ KoreanDateParser · QuickCapture(단축키)       │
 원본 Google 캘린더들 ──────────┼─Calendar API v3──▶│ Mirror: SQLite(GRDB, syncToken 2분 폴링)       │
                                │  (읽기)           │ Store: SQLite + derived/*.md                  │
 repo_paths(0~3) git log ───────┘                   │ HealthMonitor(경로 생존 신호, 1단계부터)       │
                                                    └───────┬───────────────┬──────────────────────┘
                                                            │               │
                          맥 표면 3개: ① 팝오버 "지금"  ② T-10/마무리 카드  ③ 빠른 캡처
                                                            │
                     Calendar API 쓰기 ──▶ "물길" 섀도 캘린더(7일 롤링) ──Google 동기화──▶ Galaxy Google Calendar 앱
                     Tasks API 쓰기    ──▶ Google Tasks "물길" 목록 ◀── 완료·삭제 플래그만 회수
```

- 사람이 해야 하는 일은 다음 넷뿐이다. 녹음 버튼 누르기(정지·저장 포함), 회의가 끝날 때 한 줄 적기(또는 녹음 끝에 말하기), 카톡 문장을 복사해서 단축키 누르기(폰에서는 '#' 이벤트), 가끔 "맞아요/아니에요" 고르기.
- 폰 앱은 MVP에 없다【v2: 근거는 §5.3】. 폰에서 입력은 삼성 음성녹음과 Google Calendar 앱의 '#' 이벤트로, 출력은 섀도 캘린더와 Google Tasks로 이루어진다.
- Google 일정은 API로 직접 읽고 쓴다(§5.5)【v2】. 맥 캘린더 앱에 Google 계정이 추가돼 있어도 물길은 그것을 읽지 않는다.

| **Event** | `key = calendarId + (recurringEventId ‖ id) + originalStartTime`(단일 이벤트는 `calendarId + id`), series_id, kind(meeting/class/deadline/exam/adhoc/inbox), closed_state(none/marked/nothing) | 미러와 오버레이만 둔다. 제목과 시각은 로컬 미러에서 읽고, 미러는 syncToken으로 갱신한다. 진실 원천은 Google이다. `originalStartTime`은 회차를 옮겨도 바뀌지 않는 문서상 안정 키다. 회차 id 문자열은 직접 조립하지 않고 API가 준 값을 쓴다【v2】. 제목이 `#`으로 시작하면 kind=inbox이고 매칭·시리즈·T-10·섀도에서 빠진다(§5.7). **원본 이벤트에는 private 확장 속성을 포함해 절대 쓰지 않는다**(공유 이벤트면 동아리원 전원에게 노출될 수 있기 때문) |

| **Capture** | sha256, kind(audio/video/doc/paste), origin_path, local_copy_path?, recorded_at, recorded_at_source(creation_time/mtime−duration/mtime), duration, level(L0/L1), quality(ok/warn/fail) | 원본은 옮기지 않는다. 이벤트 없이도 존재할 수 있다(화면 표기 "일정 없음") |
| **Transcript/Segment** | engine, 품질 지표, [t0,t1,text] | 파생물이다. 원본과 엔진만 있으면 다시 만들 수 있다 |
| **Mark** | kind, text, due(date/datetime/없음), state(candidate/open/done/dropped), origin(closing-card / voice-keyword / paste / inbox / transcript-rule / github), event_key?, capture_id?, t?, task_id?, shadow_event_id? | **불변식: Mark = 무엇 + 기한(선택).** 우선순위, 하위 작업, 담당자 필드는 영구 금지. candidate는 사람이 확정하기 전까지 어디에도 쓰지 않는다. `task_id`는 Google Tasks 항목, `shadow_event_id`는 시각 기한 알람 이벤트다【v2】 |
| **Link** | capture↔event, method(time-overlap/manual/backfill), score | 자동으로 만든 연결은 모두 근거를 남기고, 1탭으로 해제할 수 있다 |

**의도적으로 두지 않는 것**: 지식그래프, Person 객체, 태그 체계, 폴더 트리, 자체 일정 DB(미러는 캐시일 뿐 원천이 아니다), 자체 할 일 앱.

- 【레드팀: 현실성 major】 transcribe.sh 옵션을 그대로 옮기지 않는다. `--hallucination-silence-threshold`는 `--word-timestamps True`와 함께일 때만 의미가 있다.
- 처리가 끝나도 알림을 보내지 않는다. 결과는 다음 T-10 카드와 팝오버에 나타난다【레드팀: UX major, 알림 과다】.
- 일시정지가 있었던 녹음은 duration이 실제 경과 시간보다 짧다. `mtime − duration`으로 구한 시작 시각이 늦게 잡히는 오차는 매칭의 ±15분 허용으로 흡수한다(§5.4).
- 클라우드 STT는 기본으로 꺼 둔다. 해당 프로젝트에서 `cloud_stt_allowed`를 켰고 로컬에서 2회 실패했을 때만 쓴다. 옵트인 화면에 "다른 사람의 발화가 외부 서버로 전송됨"을 적는다.
- 원본 보존【레드팀: 현실성 major】: 폰에서 녹음을 지워도 맥 Syncthing이 `ignoreDelete=true`라 `inbox/phone/` 사본이 남고, Simple File Versioning이 한 겹 더 막는다. 그래도 로컬 64kbps 압축본을 기본 보관본으로 둔다. 수신 폴더 설정이 바뀌거나 디스크를 정리하다 원본이 사라져도 카드의 녹음 링크가 살아 있게 하기 위해서다.
- 디스크【레드팀: 생존 minor】: 원본이 맥에서 지워지지 않으므로 학기 단위로 수십 GB가 쌓인다. `inbox/phone` 원본은 "64kbps 보관본 생성 + sha 검증 + 30일 경과" 뒤 `.stversions` 정리를 **제안만** 한다. 자동 삭제는 하지 않는다(§8-7). 여유 공간 < 10GB는 HealthMonitor 빨강이다(§9).

  - D0 3번에서 하나만 고르고 패키지명을 기록한다. 서명이 달라 나중에 갈아타면 재설치와 재설정이 필요하다. 고른 앱은 Play Protect 자동 제거 예외에 넣는다.
- 실행 조건: Wi-Fi에서만 동기화하고 데이터 절약(종량제) 네트워크는 제외한다. SSID 지정은 하지 않는다. Android에서 SSID를 읽으려면 위치 권한 '항상 허용'과 시스템 위치 서비스가 켜져 있어야 하고, 위치를 끄는 순간 동기화가 조용히 멈추기 때문이다【레드팀: 현실성 minor】. 충전 중 조건은 걸지 않는다.
- 최초 1회 체크리스트:
  - 모든 파일 접근 허용
  - 배터리 '제한 없음'
  - One UI "절전 예외 앱"(Never sleeping apps)
  - "사용하지 않는 앱 권한 자동 해제" 끄기
  - Play Protect 예외(Play 빌드인 경우)
  - 녹음 앱의 "자동 언어 감지"를 끄고 한국어로 고정
  - 삼성 캘린더 새 일정 기본 저장 계정 = Google(§5.0-0)

**맥 설정**
- `brew install syncthing`으로 설치하고 로그인 항목으로 상주시킨다. 물길은 Syncthing을 내장하지 않는다. 별도 프로세스로 두고 REST API로 상태만 본다.
- 같은 폴더를 Receive Only로 받고 `ignoreDelete=true`, Simple File Versioning을 켠다. 글로벌 디스커버리는 써도 되지만 릴레이는 끈다(§5.9-4).
- Syncthing은 mtime을 함께 동기화하고, 완료 전에는 `.syncthing.*.tmp`에 썼다가 이름을 바꾼다. **mtime 보존이 이 경로를 고른 핵심 이유다.** 삼성 파일명에는 날짜가 없어서 시각 정보는 `creation_time`과 mtime뿐이다.

**사람 행동 검증**
- 반복 행동은 녹음 시작, 정지, (있으면) 저장 탭뿐이다(D0 9번).
- 맥이 꺼져 있거나 폰이 밖에 있는 동안 녹음은 폰에 그대로 남아 있다가, 같은 Wi-Fi에서 둘 다 켜지면 자동으로 따라잡는다. 사람 손은 들지 않고 지연만 생긴다.
- 0을 깨는 위험은 넷이고, 모두 HealthMonitor가 **1단계부터** 지킨다(§9).
  - (a) One UI가 Syncthing-Fork를 죽인다 → 절전 예외로 막고, 연결 상태 경보로 드러낸다.
  - (b) OS나 앱 업데이트로 모든 파일 접근 권한이 풀리거나 녹음 앱 저장 경로가 바뀐다 → 폰은 연결돼 있는데 폴더만 조용해진다. 폴더 상태와 "연결됨 + 녹음 0" 조합으로 잡는다【레드팀: 생존 fatal】.
  - (c) Play Protect가 Play 빌드를 비활성화한다 → (a)와 같은 경보로 드러난다.
  - (d) Google의 Android 개발자 인증 확대 → 한국은 2027년 전 세계 확대 때 대상이 된다. 미등록 앱은 개발자 모드를 켜고 1일 대기 뒤 재인증하는 '고급 설치 흐름'으로 계속 설치할 수 있다(2026-08 제공). 2027년 설정 체크리스트에 이 흐름 활성화를 넣는다【레드팀: 현실성 minor】.

### 5.3 폰 경로: 폴백과 탈락 경로

**폴백 G2: FolderSync(Play) → 맥 SFTP**
- 맥에서 원격 로그인을 켜고 전용 계정을 만들어 `~/Mulgil/inbox/phone`에만 쓰게 한다. SMB 공유보다 권한 범위를 좁히기 쉬워서 SFTP를 고른다.
- FolderSync는 즉시 동기화, 업로드 전용(원격 삭제 안 함), Wi-Fi 조건으로 설정한다. Play 배포라 사이드로드 정책의 영향을 받지 않는다.
- 약점:
  - 업로드 시 mtime 보존은 공식 문서가 없다. 개발자 포럼 답변은 SFTP에서 수정 시각을 설정한다고 한다. G2로 갈 때 "SFTP 업로드 뒤 mtime이 원본과 같은가"를 한 줄로 확인한다. 같지 않으면 m4a `creation_time` 의존도가 커진다【레드팀: 현실성 minor】.
  - 맥이 꺼져 있으면 폰 쪽 재시도에 의존한다.
  - 연결 상태 API가 없다. 마지막 수신 시각과 "녹음 0" 조합으로 대신 점검한다.
- 전환 조건: D0 3번에서 녹음 1건 이상 누락, D0 4번에서 생존 실패, 또는 고급 설치 흐름으로도 Syncthing-Fork 설치·업데이트 불가.

**탈락**
- Quick Share, QuickDrop, LocalSend: 녹음마다 손으로 공유해야 해서 P1 위반이다.
- Google Drive, OneDrive, Samsung Cloud: Voice Recorder 폴더를 자동 동기화하는 공식 경로가 없다(Samsung Cloud의 Drive 중단, 갤러리–OneDrive 동기화 2026-09-30 종료, Drive 앱의 임의 폴더 자동 백업 없음은 미확인). 게다가 타인 발화를 외부로 보내 §8-6 원칙에 어긋난다.

**통화 녹음: MVP 제외**
- 동기화 대상은 Voice Recorder 폴더 하나다. `/Recordings/Call`은 넣지 않는다.
- 통화는 캘린더 이벤트와 거의 겹치지 않아 매칭의 뼈대에 기여하지 않는다. 또 상대가 녹음 사실을 모르는 녹음이라 §5.9 원칙 2와 맞지 않는다.
- "놓침:" 기록의 원인이 전화 약속인 경우가 2회 이상이면 v2에서 `/Recordings/Call`을 `kind=call`로 받는 것을 검토한다. 이때도 매칭은 하지 않는다.

**삼성 Transcript Assist: 정본으로 쓰지 않는다**
- 텍스트 내보내기는 녹음마다 ⋮ > 공유를 손으로 눌러야 한다. 자동 내보내기 경로는 찾지 못했다.
- 한국어 온디바이스 처리와 한국어 화자 분리 여부가 확인되지 않았다(삼성 자료끼리 충돌한다, 미확인). 클라우드 전사 관련 변경 보도도 있다(본문 미열람).
- 폰에서 훑어보는 용도로만 쓴다. D0 12번에서 m4a 안에 전사 atom이 있으면 품질 게이트 비교용으로만 쓴다.

**Android 동반 앱: MVP에 넣지 않는다**【v2】
- 매칭에 더하는 가치가 작다. 기본 녹음 앱 + 보존된 mtime + duration만으로 녹음 구간 R을 결정론적으로 얻는다. 이벤트 ID 사이드카가 더 해 주는 것은 "겹치는 두 이벤트"와 "일정보다 일찍 시작한 녹음" 정도이고, 이 둘은 §5.4 점수식과 "확인할 것"이 이미 처리한다.
- 신뢰성이 오히려 떨어진다. 삼성 녹음 앱의 녹음 시작을 감지할 공개 API는 없다(미확인). 그러면 동반 앱이 녹음기 자체가 돼야 하고, 녹음 버튼 습관을 다시 들여야 하며, 마이크 포그라운드 서비스와 One UI 앱 종료와 새로 싸워야 한다.
- 이벤트 ID 대응도 불확실하다. Android CalendarContract의 이벤트 ID와 Google API 이벤트 ID가 1:1로 대응하는지 확인하지 못했다(미확인).
- 빌더 함정 위험이 크다. Kotlin과 Android라는 새 플랫폼은 C5가 경고한 "만드는 쾌감" 경로다. 열리는 조건은 §10.4에 두 개만 적었고, 둘 다 측정 두 번과 코드 없는 대안 시험을 먼저 요구한다.

### 5.4 녹음 ↔ 이벤트 매칭 (결정론)

```
R = [recorded_at, recorded_at + duration]; 종일 일정, '무시' 캘린더, '#' 수신함 이벤트는 제외
후보 E: R과 겹치거나 시작 시각이 ±15분 이내
score = 0.7·|R∩E|/min(|R|,|E|) + 0.15·(같은 시리즈 최근 녹음 이력) + 0.15·(캘린더 출처 일치)
score ≥ 0.6 이고 1·2위 차 ≥ 0.2 → 조용히 연결(카드에 "다른 일정이었어요?" 링크)
애매함   → 팝오버 "확인할 것"에 후보 2~3개 + [일정 없음] + [이 시각에 회의 있었음]
겹침 없음 → 기본값 [일정 없음]. 소급 이벤트는 제안만 하고 캘린더를 오염시키지 않음
```

- 매칭률은 캘린더가 실제와 얼마나 맞는지에 달려 있다. 그래서 §5.0의 0번 감사와 §5.7의 카톡 캡처가 녹음 파이프라인의 전제 조건이다.
- 1~2단계 기간에는 팝오버 하단에 "어제 일정 매칭 2/3"을 한 줄로 보여 준다(보정 기간, 이후 숨김)【레드팀: 생존 fatal】.
- 매칭에 실패한 녹음은 원인을 셋으로 분류해 `pipeline.jsonl`에 남긴다: 겹침(두 이벤트), 조기 시작, 캘린더에 없음. §10.4의 v2 분기가 이 분류를 쓴다【v2】.
- **"캘린더에 없음"이 한 주에 2건 이상이면** 팝오버에 한 줄을 띄운다: "이 시각 일정이 Google에 없어요 · 폰 캘린더 저장 계정 확인 ›". 삼성 캘린더가 일정을 삼성 계정/휴대전화에 저장하는 경우를 잡기 위해서다. §11-①의 조기 신호다【레드팀: 생존 fatal】.

### 5.5 캘린더: Google Calendar API 직접 연동

【v2】 v1은 "Google OAuth 테스트 앱의 refresh token 7일 만료"를 피하려고 macOS 인터넷 계정 + EventKit을 골랐다. 7일 만료는 Testing 상태의 테스트 사용자에게 문서화된 규칙이고, 동의 화면을 '프로덕션'으로 게시하면 사라진다고 본다. 단 게시 후에도 만료됐다는 포럼 보고가 있으므로 D0 1번에서 8일 뒤까지 실측한다【레드팀: 현실성 minor】. API로 바꾸는 이유는 다섯이다.
1. 회차 키: `recurringEventId + originalStartTime`은 문서로 보장된 안정 키다. EventKit의 `externalIdentifier + occurrenceDate`는 Google 소스에서 회차를 옮긴 뒤에도 안정적인지 확인되지 않았다.
2. 반영 지연: 폴링 주기를 앱이 정한다. macOS 캘린더의 Google 새로 고침은 기본 5분이고 1분 옵션은 확인되지 않았으며, `refreshSourcesIfNecessary`는 실시간이 아니라는 보고가 있다.
3. 섀도 캘린더: `calendars.insert`로 앱이 직접 만들고 지운다. 웹에서 손으로 만드는 온보딩 단계가 사라진다. EventKit으로는 Google 캘린더를 만들 수 없다.
4. 섀도 이벤트를 원본 키로 다시 찾기: `extendedProperties.private`에 원본 키를 넣고 `privateExtendedProperty` 필터로 조회한다. notes 파싱이 필요 없다.
5. 할 것을 Google Tasks로 내보내는 일은 어차피 API로만 할 수 있다.

**인증**
- 데스크톱 OAuth 클라이언트, loopback 리다이렉트(`http://127.0.0.1:<port>`) + PKCE. 데스크톱 클라이언트의 client_secret은 비밀로 취급되지 않는다.
- 스코프: `calendar`(보조 캘린더 생성 때문에 `calendar.events`로는 부족하다), `tasks`.
- refresh token은 Keychain에 **하나만** 둔다. 다시 로그인할 때 새 토큰을 쌓지 않는다. Google 계정·클라이언트당 refresh token은 100개까지이고 넘으면 가장 오래된 것이 조용히 무효화되므로, 개발 중에는 옛 토큰을 revoke한다. 6개월 동안 쓰지 않은 토큰도 만료된다【레드팀: 현실성 minor】.
- `invalid_grant`가 오면 HealthMonitor가 고장 문구 한 줄로 알린다(§7.11).

**동기화**
- 캘린더별로 `events.list(syncToken)`를 돌린다. 기본 2분 간격, 맥이 깨어날 때(`NSWorkspace.didWakeNotification`)와 T-10 계산 직전에는 즉시 돈다. `nextSyncToken`은 마지막 페이지에만 온다.
- 410 GONE이 오면 그 캘린더의 미러를 비우고 토큰 없이 전체 동기화한다. 삭제된 이벤트는 `status=cancelled`로 받는다.
- push(watch) 알림은 공개 HTTPS 주소가 필요해서 서버 없는 메뉴바 앱은 쓸 수 없다. 그래서 폴링한다. 쿼터는 사용자당 분당 600요청이고, 캘린더 5개를 2분마다 돌리면 분당 3요청 안팎이다.
- 시작 20분 이내에 처음 발견한 회의는 맥 카드만 띄우고 섀도 쓰기는 생략한다【레드팀: 현실성 minor】.
- `quickAdd`는 쓰지 않는다. 한국어 날짜 파싱 근거가 없다(영어 예시만 있음). 날짜 해석은 로컬 KoreanDateParser 하나가 맡는다.

**대체 경로 (a): D0 1번이 실패할 때만**
- macOS 인터넷 계정에 Google을 추가하고 EventKit으로 **읽기만** 한다. 회차 키는 `externalIdentifier + occurrenceDate`.
- 섀도는 웹에서 손으로 만든 보조 캘린더에 EventKit으로 쓴다. Tasks 회수는 포기하고 확정 owe는 섀도 알람 이벤트로만 표시한다.
- 미러 계층은 1단계부터 `CalendarSource` 프로토콜 하나 뒤에 둔다. 구현은 API 하나만 쓰고, (a) 구현은 실패가 확정된 뒤에만 쓴다. **두 경로를 동시에 운영하지 않는다**(엔진 이원화 금지와 같은 원칙).

### 5.7 약속 캡처: 입력이 0이 될 수 없는 곳

**사실 정리**【레드팀: 현실성 major】
- 카톡 대화는 읽을 수 없다. 카카오 메시지 API는 보내기 전용이다.
- 톡캘린더 REST API는 "사용 권한이 주어진 앱"에서만 쓸 수 있다(문서 원문 미열람). 톡캘린더 → Google 캘린더 내보내기 공식 기능은 확인되지 않았다. 공식 소개에는 휴대폰 캘린더 → 톡캘린더 방향만 있다.
- Android 카카오톡에서 메시지를 길게 누르면 복사가 있다(2탭, 확실). '공유'는 카톡 안 채팅방을 고르는 흐름으로 소개되고, 외부 앱으로 평문을 넘기는지는 미확인이다(D0 7번).
- 그래서 카톡 경로는 사람이 넘겨주는 수동 경로이고, 이 경로를 최고로 매끄럽게 만드는 것이 승부처다.
- **원칙: 물길은 내가 넘긴 문장만 본다.** NotificationListener와 DB 복호화는 쓰지 않는다(§10.5).

**맥: 빠른 캡처**
- 카톡 문장을 복사하고 단축키를 누른다. 기본값은 **⌃⌥⌘M**이다【레드팀: 현실성 major】.
  - ⌃⌥Space는 macOS 기본 "입력 메뉴에서 다음 소스 선택"과 겹쳐 한/영 전환을 깨므로 쓰지 않는다.
  - 온보딩에서 `com.apple.symbolichotkeys`의 입력 소스 단축키와 Raycast/Alfred 기본값과의 충돌을 검사한 뒤 녹화로 고르게 한다. macOS 15부터 `RegisterEventHotKey`는 Option이나 Shift+Option만 쓴 조합을 거부하므로(-9868), 녹화기는 Control이나 Command가 없는 조합을 받지 않는다.
  - 단축키는 Carbon `RegisterEventHotKey`로 등록해 접근성 권한을 받지 않는다.
- 클립보드 내용이 미리 채워진다. 로컬 규칙 파서가 기준 시각을 "붙여넣은 시각"으로 잡고 다음 표현을 해석한다: 내일, 모레, 다음 주 X요일, 수욜/목욜, N시 반, 저녁=19시. NSDataDetector는 보조로만 쓴다.
- 프로젝트 칩은 최근 3개만 보이고, 별칭이 일치하면 하나를 미리 골라 둔다. Enter 한 번으로 끝난다.
- "일정으로 ⏎"는 내 기본(primary) Google 캘린더에 `events.insert`로 넣는다. 내가 확정한 것이므로 §8-1에 어긋나지 않는다. 이렇게 넣은 일정은 "캘린더 밖에서 들어온 일정"으로 집계된다(§10.2).
- 한국어 IME 조합 중 Enter는 확정으로 처리하지 않는다(`markedText` 확인).
- 실제 카톡 문장 50개와 IME 시나리오로 회귀 테스트 세트를 만든다.
- "놓침: …"으로 시작하는 입력은 놓친 일정/약속으로 기록된다(성공 지표 5번).

**폰: 수신함 (앱 없음)**【v2】
- 기본 경로: 카톡 길게 누르기 → 복사 → Google Calendar 위젯이나 앱의 '+' → 제목에 `#` + 붙여넣기 → 저장. 약 6탭이다(D0 7번에서 실측).
- 제목이 `#`으로 시작하는 이벤트는 어느 캘린더에 있든 수신함 항목으로 취급한다. 처리 규칙【레드팀: 생존 major】:
  - **매칭, 시리즈 생성, T-10, 섀도 대상에서 뺀다.** 폰에서 '+'로 만든 이벤트는 "다음 정시" 같은 기본 시각에 기본 알림까지 붙어 저장되므로, 실제 일정처럼 다루면 녹음이 엉뚱하게 붙는다.
  - 날짜 파싱 기준 시각은 이벤트의 `created`다(이벤트 시작 시각이 아니다).
  - 맥이 처음 읽는 즉시 `events.move`로 "물길 수신함" 캘린더로 옮기고 알림을 지운다. primary를 동아리와 공유하더라도 원문이 오래 노출되지 않는다. 이것은 원본 쓰기가 아니라 내가 넣은 수신함 항목을 처리하는 일이므로 §8-1에 걸리지 않는다.
  - 팝오버 "확인할 것"에 올리고, 확정하면 정식 이벤트나 Mark로 옮긴 뒤 `#` 이벤트를 지운다. 7일 동안 확정되지 않으면 수신함 캘린더에서 지우고 `pipeline.jsonl`에만 남긴다.
- Gemini "Add to my calendar"(붙여넣기 또는 화면 질문)로 만든 일정은 그냥 보통 일정으로 들어온다. 물길은 Gemini에 의존하지 않고, 이것은 내가 고르는 선택적 입구일 뿐이다(LLM 비핵심 원칙). 한국어·카톡 화면 동작은 미확인이다.
- One UI 텍스트 선택 '일정 추가' 스마트 액션이 한국어 날짜를 인식하면(미확인) 코드 0으로 탭 수가 더 줄어든다.

**회의 마무리: 맥이 없을 때도 되게**【레드팀: 생존 fatal】
1. 맥 앞에 있으면 T-10 카드가 회의 종료 시 마무리 모드로 뒤집힌다(§7).
2. 녹음 중이면 멈추기 전에 이렇게 말한다. "물길, 내가 할 것: 연사 리스트 금요일까지." **0탭이라 1순위다.**
   - 삼성 음성녹음 → Syncthing → 파이프라인이 마지막 90초에서 호출어를 퍼지 매칭(물길/물 길)으로 찾는다. 새 코드는 맥에만 있다.
   - 그 구간을 규칙으로 잘라 `origin=voice-keyword`인 **확정 Mark**(t 포함)로 저장한다.
   - 사람의 발화가 곧 확정이므로 candidate가 아니다. 팝오버에서 "되돌리기"만 할 수 있다.
   - 호출어 인식률은 미검증이다. 3단계에서 10회 발화로 측정하고, 인식률이 80% 미만이면 "이거 맞아요?" 후보로 내린다.
3. 녹음하지 않았으면 홈 화면 Google Calendar 위젯 '+' → Gboard 음성 입력으로 "#연사 리스트 금요일까지" → 저장(약 4탭).
4. 셋 다 놓치면 다음 맥 T-10 카드의 마무리 영역에 맡긴다.

- 음성 메모 위젯이나 빠른 설정 타일은 2번과 중복되므로 만들지 않는다.
- Galaxy 모드 및 루틴("앱 실행: 음성녹음 → 방해금지")은 선택 사항으로만 둔다. 녹음 종료 조건이 없고, 앱을 열 때마다 반복 실행되며, One UI 업데이트 뒤 깨진다는 보고가 있다. 핵심 경로가 아니므로 HealthMonitor 대상도 아니다.

**지난 약속의 완료 처리**: 마무리 카드가 아니라 다음 T-10 카드에서 "이거 했어요?"로 묻는다【레드팀: UX major】. Google Tasks에서 이미 완료하거나 지운 항목은 묻지 않는다(§6.3).

### 5.8 L1 규칙 후보: 이벤트 종류별로 범위 제한

【레드팀: 생존 major】

| 이벤트 kind | 뽑는 것 | 규칙 |
|---|---|---|
| class | deadline만 | "과제/제출/시험/퀴즈/마감/발표" 키워드와 날짜 표현이 같은 문장 또는 ±1문장에 있을 때. owe/wait는 끈다(교수의 "제가 다음 주에 보여 줄게요" 같은 오탐을 막기 위해) |
| meeting | owe, deadline | 1인칭("제가/내가 ~할게요/하겠습니다")과 날짜가 **같은 문장**에 있을 때. v1에는 화자 분리가 없다 |
| 그 외 | 없음 | — |

- 목표 정밀도(후보 확정률)는 ≥ 50%다. 실제 전사본 20개로 측정한 뒤 확정한다.
- 미달이면 규칙을 **줄인다.** 늘리지 않는다.
- 후보는 회색 "이거 맞아요?"로만 존재하고, 72시간 뒤 접힌다.

### 5.9 녹음 정책 (법과 윤리)

【레드팀: 현실성 minor를 원칙으로 승격】
- 통신비밀보호법상 내가 참여한 대화를 녹음하는 것은 처벌 대상이 아니라는 것이 판례 입장이다. 내가 참여하지 않은 대화를 녹음하는 것은 불법이다. 당사자 녹음에도 동의를 요구하는 개정 논의가 있었으므로 시행 전에 다시 확인한다(미확인).
- 원칙:
  1. 내가 자리를 비운 구간은 녹음하지 않는다.
  2. 다른 사람이 있는 회의에서는 녹음 사실을 알린다. 같은 이유로 통화 자동 녹음은 동기화하지 않는다(§5.3).
  3. 강의는 교수 허락을 받은 과목만 `Series.recordable=true`로 둔다. 저작물이므로 사적 이용 범위에서만 쓴다.
  4. 전사와 원본을 공유하거나 내보내는 기능은 두지 않는다. 녹음은 폰 → 맥 로컬 네트워크로만 이동한다(Syncthing 릴레이 끔).

### 6.3 섀도 캘린더와 할 것 내보내기 규칙

【레드팀: 생존 major·현실성 major】【v2】
- 앱이 `calendars.insert`로 "물길"과 "물길 수신함" 보조 캘린더를 만든다. `calendarList`에서 `defaultReminders=[]`로 둔다. 온보딩 체크리스트에는 Galaxy Google Calendar 앱에서 두 캘린더의 동기화·표시를 켜는 것까지만 넣는다(필요 여부는 D0 5번).
- **Galaxy 알림 소스는 Google Calendar 앱 하나로 정한다.** 삼성 캘린더와 함께 켜면 알림이 두 번 오거나 둘 다 안 오는 보고가 있다. 삼성 캘린더에서는 물길 캘린더를 숨기거나 알림을 끈다.
- 맥락 이벤트는 "지난 회차 녹음이나 열린 Mark가 있는 시리즈" 또는 "자료가 있는 일회성 이벤트"에만, 회의당 1개 만든다. 원본 시작 10분 전부터 10분짜리다.
- **쓰는 시점: 7일 롤링**【레드팀: 생존 major】. 맥이 깨어 있는 동안 앞으로 7일 치 맥락 이벤트를 채워 둔다. 깨어날 때 즉시 채우고, 이후 syncToken 폴링에서 원본 변경이나 Mark 변경이 보일 때마다 옮기거나 고치거나 지운다. 맥을 며칠 덮어 두어도 이미 채워 둔 7일 치는 폰에 남는다. 정해진 시각에 쓰는 방식이나 `pmset` 예약 깨우기는 쓰지 않는다.
- 섀도의 `extendedProperties.private`에 `{mulgil_src: 원본 키, mulgil_v: 기준 시각}`을 넣는다. 다시 찾을 때는 `privateExtendedProperty=mulgil_src=<키>`로 조회한다. 원본 이벤트에는 아무것도 쓰지 않는다.
- **알람은 기본으로 넣지 않는다.** 폰 알림은 원본 알람이 맡는다. 원본 알림을 눌러 캘린더를 열면 바로 위에 맥락 이벤트가 보인다. 맥이 덮인 동안 원본이 바뀌면 섀도가 낡을 수 있으니, 낡은 이벤트에 알람이 울리는 것을 막기 위해서다. description 첫 줄에 마지막 갱신 시각(`기준 11/23 07:30 · 원본 일정 확인`)을 넣는다.
- 일요일 문장에 "섀도 있던 회의 / 전체 회의"를 넣는다. "폰에서 안 봤다"와 "폰에 아예 없었다"를 구분하기 위해서다. v2 분기(§10.4)는 섀도가 있었는데도 안 본 경우에만 위젯/ntfy로 간다.
- **확정 owe 내보내기**:
  - Google Tasks "물길" 목록에 확정 owe만 쓴다. Tasks API의 due는 날짜만 저장한다(시간은 버려지고 00:00 UTC로 돌아온다).
  - **한 번 만든 Tasks 항목의 due는 다시 PATCH하지 않는다.** Google Calendar 앱에서 끌어 옮긴 날짜와 API가 쓴 날짜가 어긋나는 문제가 있기 때문이다(issuetracker 170143566). 기한이 바뀌면 항목을 지우고 새로 만들어 `task_id`를 바꾼다【레드팀: 현실성 minor】.
  - datetime 기한이 있는 owe는 Tasks 항목과 함께 "물길" 캘린더에 **기한 1시간 전 popup override 알람 이벤트**를 만든다. API로 만든 Tasks 항목은 시간이 없어 폰 알림이 울리지 않을 가능성이 높기 때문이다. 같은 날 3개를 넘으면 하나로 합친다. popup이 Galaxy에서 실제로 울리는지는 D0 5번에서 실측한다.
  - **완료·삭제 플래그만 읽어 온다.** `tasks.list(showCompleted=true, showHidden=true, showDeleted=true, updatedMin=마지막 폴링)`로 `status=completed`면 Mark를 done으로, `deleted=true`면 dropped로 바꾸고 로그에 남긴다. 삭제로 접은 것은 "되돌릴 수만 있는 것"에 한 번 보여 준다【레드팀: 생존 minor】. 제목·기한을 고친 내용은 회수하지 않는다. 이렇게 해서 이미 끝내거나 버린 일이 T-10 카드에서 미완으로 경고되는 일을 막는다.
  - 이 할 일은 삼성 캘린더에는 보이지 않고 Google Calendar 앱과 Tasks 앱에서만 보인다(사용자 보고). 폰 기본 캘린더 앱을 Google Calendar로 쓰는 것이 전제다(§12).
  - D0 6번이 실패하면 Tasks를 빼고 알람 이벤트만 쓴다. "섀도 종일 이벤트로 할 것 표시"는 완료 체크를 회수할 방법이 없어 §11-③ 신뢰 붕괴를 다시 만들므로 쓰지 않는다.

### 6.4 겹치는 회의와 연속 회의

- 앞 회의의 마무리 모드와 다음 회의의 T-10이 겹치면 카드 하나에 두 영역을 위아래로 둔다. 위가 마무리, 아래가 다음 회의다. 마무리는 [나중에] 없이도 접히면 "확인할 것"으로 넘어간다.
- 동시에 겹친 두 이벤트는 녹음 매칭 점수로만 정한다. 카드는 내가 수락한(attendees의 self `responseStatus=accepted`) 이벤트를 우선한다.

## 7. UI/UX

### 7.1 원칙

1. **시간이 레이아웃이다.** 세로축은 항상 시각이다. 폴더, 트리, 그래프 뷰는 없다.
2. **카드 하나에 질문 하나.** 표면은 3개뿐이다(§6.1).
3. **정상일 때는 침묵한다.** 파이프라인 상태는 고장일 때만 문장 한 줄로 보여 준다. 메뉴바 아이콘은 평소 단색이고, 고장일 때 **모양**이 바뀐다(색이 아니라). 노란 상태, 빨간 배지, 미처리 카운터, "2/4" 같은 진행 표시는 없다【레드팀: UX major】.
4. **색은 프로젝트에만 쓴다.** 크롬은 시스템 머티리얼과 무채색이다. 프로젝트 색은 3px 막대와 칩에만 쓰고, 강조색은 1개(기한 임박)다.
5. **원본까지 한 번에.** 모든 문장 옆에 타임코드 칩 `‹23:41›`을 두고, 누르면 5초 전부터 재생한다.
6. **확정과 후보를 구분한다.** 내가 적은 것은 진한 본문체, 자동 후보는 회색 + "이거 맞아요?"로 쓴다. 미정은 지우지 않는다.
7. **빈 화면이 가장 아름다워야 한다.** "오늘 열린 약속 없음"은 여백에 문장 하나로 보여 준다.

### 7.2 디자인 토큰

- **기호 사전(이 4개 외에는 코드 리뷰에서 거부)**: 녹음 `waveform`(ASCII ◉), 자료 `doc`(▤), 약속 `circle`/`checkmark.circle`(○/●), 기한 `flag`(⚑). UI에 이모지는 금지한다. ❓ 대신 텍스트 "미정"을 쓴다【레드팀: UX major】.
- **타이포**: SF Pro + Apple SD Gothic Neo. 크기는 28/17/13/11 네 단계. 시각은 tabular 숫자, 타임코드는 SF Mono.
- **간격**: 4/8/12/16/24.
- **모션**: 2개뿐이다. 카드가 메뉴바에서 내려오는 것(220ms ease-out)과 확정 체크(150ms). 사운드는 없다.
- **색**: 프로젝트 8색. 한번 배정하면 영구 고정하고, 이번 주 비활성 프로젝트는 회색으로 둔다. 같은 화면에 같은 색이 두 번 나오면 칩에 이니셜을 함께 쓴다.

### 7.3 UX 라이팅 표 (화면에 내부 용어를 쓰지 않는다)

【레드팀: UX major】 레포에 `copy.md`로 두고, 문구 변경도 리뷰한다.

| 내부 | 화면 |

| candidate / 후보 | 이거 맞아요? |
| owe | 할 것 |
| wait | 기다리는 것 |
| decision | 정한 것 |
| question / ❓ | 미정 |
| 개인 메모(이벤트 없음) | 일정 없음 |
| 즉석 회의 소급 | 이 시각에 회의 있었음 |

    2. 맨 앞 앱의 번들 ID가 Keynote/PowerPoint/zoom.us이고 화면 전체를 덮는 창이 있음(번들 ID와 창 크기는 권한 없이 읽힌다).
    3. 집중 모드(`INFocusStatusCenter.isFocused`, 알림 권한을 받은 뒤에만).
  - 셋 다 판단할 수 없으면 카드 대신 점을 찍는 쪽으로 기운다.
- LLM을 꺼도 이 카드는 완전하다. 확정 Mark, 녹음 링크, 파일, 커밋이 모두 결정론적으로 나온다.

### 7.10 폰 맥락 이벤트 서식 규격

【레드팀: UX major】【v2】

```
제목: · AUSG 운영 회의 맥락
description(최대 6줄, 줄당 40자, 넘치면 "…"):
1 기준 11/23 07:30 · 원본 일정 확인
2 정한 것: 12월 밋업 장소 = 판교
3 미정: 예산 승인 주체
4 할 것: 연사 리스트 공유(오늘) — 남음
5 기다리는 것: 예산안 ← 민지
6 https://… (원본의 Zoom/Meet/Notion 링크. 없으면 줄 생략)
```

- 링크는 https 원문 URL만 쓴다. Android 캘린더 앱은 커스텀 스킴을 열지 않는다.
- 2단계 완료 조건: Galaxy Google Calendar 앱(일정 보기와 상세 화면)에서 렌더링한 스크린샷으로 검증한다. 삼성 캘린더는 물길 캘린더를 숨기지 않은 경우에만 표시를 확인한다.
- 섀도가 있었는데도 폰에서 맥락을 본 비율이 미달이면 v2 첫 순위는 Galaxy 홈 화면 위젯이다. 직접 만들기 전에 Google Calendar/Tasks 기본 위젯 배치로 먼저 해결되는지 본다. 안 되면 ntfy 푸시로 간다.

| 폰은 연결됨 + 녹음 폴더 오류·정체 | 폰은 연결됐는데 녹음 폴더를 못 읽고 있어요 · 폰 권한 확인 › |

### 7.12 키보드와 접근성

- 키보드: 팝오버 ⌘1, 검색 ⌘F, 빠른 캡처 ⌃⌥⌘M(변경 가능), 카드에서 ⏎ 저장 / ⌘⏎ 약속 / Esc 접기, 확인할 것에서 ←/→ 아니에요/맞아요, ⌘Z 되돌리기. 키보드만으로 전체 흐름을 쓸 수 있어야 한다.
- 접근성: 모든 기호에 VoiceOver 레이블을 붙인다(예: "녹음 52분"). 동적 글자 크기를 지원한다. 색 말고 이니셜과 기호로도 구분할 수 있게 한다.

### 7.13 아름다움을 검증하는 방법

MVP 각 단계의 완료 조건에 "Things 3 Today, Cron 팝오버와 나란히 놓은 스크린샷 리뷰"를 넣는다. 기준은 세 가지다: 기호 수, 줄 수, 위계(히어로 하나).

## 8. AI의 역할 경계

| AI(모델)가 하는 것: 보이지 않는 배관 | 방식 |
|---|---|
| 음성 → 텍스트 | 로컬 mlx-whisper 또는 SpeechTranscriber(D0 승자 1개) + VAD |
| (v2) 화자 분리 | FluidAudio(Swift/CoreML, 오프라인). 이름 후보는 이벤트 참석자 |

| 규칙(비AI)이 하는 것 |
|---|
| 녹음-이벤트 매칭, 시리즈 → 프로젝트 상속, 한국어 날짜 파싱, Mark 종류 추론, L1 후보 추출, 호출어 구간 자르기, initial_prompt 조립, 접기와 만료, 알림 시점, 지표 집계. 모두 단위 테스트와 회귀 세트로 검증한다 |

**절대 하지 않는 것**
1. 내가 확정하지 않은 것을 Google 캘린더, Google Tasks, 섀도 캘린더에 쓰기. (내가 넣은 `#` 수신함 항목을 수신함 캘린더로 옮기고 지우는 것은 예외다. §5.7)
2. 요약 산문을 주인공으로 두기. 카드의 주인공은 내가 적은 정한 것·할 것과 원본 타임코드다.
3. 출처(타임코드, 파일) 없이 말하기.
4. 프로젝트를 만들거나 바꾸거나 판단하기.
5. 핵심 루프에 들어가기. LLM off 스위치가 있고, 꺼도 100% 동작한다. 채팅 창과 `claude -p` 브리지는 없다. Gemini 같은 폰 쪽 LLM 입구는 내가 고를 수 있는 바깥 경로일 뿐 물길이 의존하지 않는다.
6. 기본 설정으로 타인의 발화를 외부에 보내기. 녹음 동기화에 클라우드 경로와 릴레이를 쓰지 않는 이유이기도 하다(§5.3, §5.9).
7. 파일 이름을 바꾸거나, 옮기거나, 지우기.

**L2(시험 정리본)와 Claude Code**: 시험 이벤트(kind=exam)가 있을 때만 이벤트 상세에 [시험 정리본 만들기]가 생긴다. 이 버튼은 고른 주차의 `transcript.md` 경로 목록과 `/home/user/yc-lecture/CLAUDE.md` 노트 규칙 경로를 `~/Mulgil/export/l2-request.md`로 내보낼 뿐이다. 노트 작성은 제품 밖에서 Claude Code로 한다. 제품은 Claude에 의존하지 않는다.

**저장 구조**
```
~/Mulgil/

  audio/<sha>.m4a                # 로컬 압축 보관본(64kbps mono)
  derived/<sha>/transcript.json  # 세그먼트, 엔진, 품질 지표
  derived/<sha>/transcript.md    # 헤더에 출처/이벤트/엔진. grep 가능
```

**서명과 권한**【레드팀: 현실성 minor】
- 항상 같은 Apple Development 인증서(Personal Team도 가능)로 서명하고, 번들 ID를 고정한다. 그래야 다시 빌드해도 Keychain 접근, 알림, 폴더 접근 권한이 풀리지 않는다.
- 샌드박스는 끄고, 파일은 경로와 sha로만 참조한다.
- 앱 시작 시와 macOS 업데이트 후 첫 실행 시 권한·토큰·Syncthing 연결을 자가 점검한다.

**HealthMonitor: 경로 생존 신호**【레드팀: 생존 major(1차)·생존 fatal(2차)】【v2】

경로가 생긴 날부터 감시한다. Google·Syncthing 부분은 **1단계**에 만들고(1단계 백필이 이미 녹음 메타데이터를 읽으므로 "마지막 녹음 도착 시각"은 공짜로 나온다), 전사·에셋·디스크 부분은 3단계에 더한다. 매시간, 그리고 깨어날 때 점검한다.

| 구분 | 점검 내용 | 단계 |
|---|---|---|
| 빨강(알림 + 아이콘 모양) | 폰 미연결: `/rest/system/connections`의 `connected`가 false이고 마지막 연결 > 24h(집 Wi-Fi 전용이면 48h). `lastSeen`은 보조로만 쓴다 | 1 |
| 빨강 | **폴더 단위 고장**: `/rest/db/status`의 폴더 상태가 error/stopped, 폰 쪽 폴더 완료율이 정체, 폰이 광고하는 폴더 파일 수가 줄거나 멈춤(필드명은 D0 4번에서 실측). 폰은 연결됐는데 폴더만 조용한 상태가 권한 해제·저장 경로 변경의 지문이다 | 1 |
| 빨강 | 맥 Syncthing 프로세스 미실행 · `inbox/phone` 경로 소실 · Google `invalid_grant` | 1 |
| 빨강 | ko 에셋 소실 · 원본 경로 소실 · `~/Mulgil` 볼륨 여유 < 10GB【레드팀: 생존 minor】 | 3 |
| 확인 필요(알림 없음, 팝오버 맨 위 한 줄 + 아이콘 모양) | "수업·회의 3개 연속 종료 + 녹음 0 + 폰 연결됨" 조합. 녹음을 안 한 날과 구별되는 고장 후보다 | 1 |
| 정보(팝오버 첫 화면 한 줄) | "어제 끝난 수업·회의 3개 · 녹음 0" · Downloads/Documents 접근 상실 · "캘린더에 없음" 주 2건 이상 | 1·3 |

녹음 수가 0인 것**만으로는** 빨간불을 켜지 않는다. 그냥 녹음을 안 한 날과 고장을 구분할 수 없어서, 오경보가 쌓이면 진짜 고장까지 무시하게 되기 때문이다. 그래서 "녹음 0"은 항상 "폰 연결됨"이나 폴더 상태와 짝지어서만 쓴다. 같은 이유로 Galaxy 모드 및 루틴은 점검하지 않는다. 경보가 실제로 뜨는지는 D0 4번 고장 주입으로 확인하고, 1·2단계 소크 기간의 오탐 수를 2단계 통과 조건에 넣는다(§10.1).

**철수 경로**【레드팀: 생존 missing】
- 메뉴 → "물길 그만 쓰기"는 다음을 한다: "물길"·"물길 수신함" 캘린더를 `calendars.delete`로 삭제, Tasks "물길" 목록 삭제, OAuth 토큰 revoke, marks.jsonl과 transcript.md 내보내기, 로그인 항목 해제.
- Syncthing 폴더 공유는 그대로 둔다. 원하면 폰과 맥에서 공유를 끄는 방법을 한 화면으로 안내한다.
- 원본 녹음은 건드리지 않는다.

- 분모(캘린더에 있는 회의·수업)가 주 5건 미만인 주는 "표본 부족"으로 표시하고 계산에서 뺀다. 측정 1차의 유효 주가 하나도 없으면 1/7 판정은 "계속(측정 2차까지 보류)"으로 기록하고, 측정 2차 결과로 판정한다.
- 성공 기준(§10.2) 1번이 미달이면, 다른 결과와 무관하게 "한 지점만 고침: 파이프라인"이다.
- 7개 중 5개 이상 통과 → **계속.** 실패 지표로 §10.4 v2 순서를 정한다.
- 3~4개 통과 → **한 지점만 고침.** §11-⑫의 3질문으로 한 지점을 골라 고치고 다음 측정에서 다시 본다.
- 2개 이하, 또는 판정 2차에서도 "한 지점만 고침"이 반복 → **철수**(§9 철수 경로).

- **측정 분모를 미리 넣는다(D0)**: g1-teleop·gomap 주간 셀프 싱크, 해커톤, 동아리 정기 회의를 캘린더에 반복 이벤트로 넣는다. 측정은 캘린더에 있는 이벤트만 분모로 삼는다. 캘린더 밖 신호는 §10.2 8번이 따로 본다.
- 1단계 범위에서 뺀 것: Week 뷰, 준비 블록, 일요일 창, 시험 알림, FTS(3단계로), 화자 분리, 엔진 이원화, 클라우드 STT, 폰 앱.

### 10.2 성공 기준 (앱이 집계해 일요일 문장으로 보여 준다)

1. 녹음 100%가 녹음 앱 밖 수동 명령 0회로 L0에 도달한다(실패도 "표시됨"으로 집계). **이 항목이 미달이면 UI 작업을 전면 중단하고 파이프라인만 고친다.**
2. 일정 매칭률 ≥ 80%. 미달이면 매칭 실패 원인 분류(§5.4)를 보고 §10.4의 해당 행으로 간다.
3. 정기 회의 중 마무리된 비율(카드, 말, 수신함, [없었음] 포함) ≥ 70%.
4. 맥락 카드(맥 또는 폰)를 보고 들어간 회의 비율 ≥ 50%.
5. "놓침:" 기록이 주 0~1건.
6. L1 후보 확정률 ≥ 50%.
7. 하루 이상 쉬었다 돌아왔을 때 할 일 0.
8. **캘린더 밖 신호가 늘지 않는다**【레드팀: 생존 major】. "이벤트와 매칭되지 않은 녹음 수"와 "빠른 캡처나 `#`로 들어왔지만 원래 캘린더에 없던 일정 수"를 주마다 센다. 둘 다 2주 연속 늘면 일요일 문장에 "캘린더가 실제를 놓치고 있어요"를 붙인다. 1~4번은 캘린더에 있는 것만 분모로 삼으므로, 캘린더가 비어 갈수록 좋아 보인다. 5번은 내가 적는 값이라 물길을 덜 열수록 0이 된다. 8번이 그 둘을 견제한다. 측정 1차 끝의 D0 0번 재감사와 함께 본다.

### 10.3 빌더 함정 차단 장치

【레드팀: 생존 major】【v2】 외부 승인자는 없다. 동결은 도구가 지키고, 우회한 흔적은 숨기지 않는다.
- **동결 달력 파일**: 레포의 `freeze.txt`에 §10.1의 실사용·측정 기간을 적는다. `pre-commit`과 `pre-push` 훅이 그 기간에 `fix:`가 아닌 커밋을 거부한다. GitHub Actions도 main 머지 시 같은 검사를 한다.
- **우회는 계정 전체에서 보인다**【레드팀: 생존 major】: `--no-verify`, 훅 삭제, 새 레포 만들기로 우회할 수 있다. 그래서 일요일 문장에 다음을 넣는다. 0이 아니면 숫자가 그대로 보인다.
  - 물길 레포의 동결 기간 비버그 커밋 수(git log).
  - 동결 기간에 내 계정에 **새로 만든 레포 수**(`gh repo list --json createdAt`).
  - 동결 기간에 내 계정 어디서든 `.kt`/`.kts`/`build.gradle`을 건드린 커밋 수(`gh api /users/<me>/events`의 PushEvent).
- **커밋 훅**: `commit-msg`에서 `fix:` 커밋에 `bugs.md:<날짜>` 참조를 필수로 요구한다. 그리고 `bugs.md`의 각 항목은 그 버그를 보여 주는 `usage.jsonl` 또는 `pipeline.jsonl` 라인 번호를 함께 적어야 한다. 그 자리에서 한 줄 써서 통과하는 자기 승인을 어렵게 하기 위해서다.
- **동결 예외는 하나뿐이다**: D0 1번이 12/1에 실패하면 `fix: D0-1`로 대체 경로 (a) 전환만 허용한다. 범위는 `CalendarSource` 구현 교체로 제한한다.
- **아름다움 욕구의 허가된 출구**: 동결 중에도 팝오버와 카드의 **시각 다듬기만** 하루 1시간까지 허용한다(`polish/` 브랜치, 새 필드·새 화면 금지). 측정 1차에서 성공 기준 3개 이상을 통과하면 디자인 스프린트 3일을 보상으로 둔다.
- **2회 규칙**: 새 기능은 `ideas.md`에 "실제로 필요했던 날짜"가 2개 이상 있어야 후보가 된다.
- **새 플랫폼 금지**: MVP 기간에 Kotlin/Android 코드를 쓰지 않는다. 동반 앱은 §10.4 조건을 모두 통과해야 연다.
- **빌더 에너지의 행선지**: 물길 밖(해커톤, gomap 등)으로 돌린다고 명시한다.
- **이 문서를 더 다듬지 않는다.** 다음 수정은 D0 결과를 반영할 때만 한다.

### 10.4 v2 후보 (어느 지표가 실패했는지로 순서를 정한다)

| 조건 | 후보 |
|---|---|
| **섀도가 있었는데도** 폰에서 맥락을 본 비율이 낮음 | Galaxy 홈 화면 위젯(먼저 Google Calendar/Tasks 기본 위젯 배치로 해결되는지 본다) → ntfy 푸시. 섀도가 아예 없었던 것이 원인이면 섀도 롤링을 먼저 고친다 |

| ⑫ **결국 안 쓴다** | 14일 중 팝오버를 연 날 < 7 | 기능을 더하지 말고 3질문만 묻는다. (a) 녹음이 자동으로 들어왔나? (b) 카드가 회의 전에 떴나? (c) 떴는데 안 봤다면 내용이 비었나, 타이밍이 틀렸나? 답이 가리키는 한 지점만 고친다. 날짜가 정해진 판정(§10.1, 1/7과 판정 2차)에서 철수가 나오면 철수 경로(§9)로 깨끗하게 끝낸다【레드팀: 생존 major】 |

**가장 약한 고리**는 기술이 아니라 회의 종료 직후의 한 줄이다. 그래서 설계는 두 가지를 지킨다. 첫째, 그 한 줄이 무너져도 녹음, 캘린더, 섀도 출력은 계속 돈다. 둘째, 의식은 늘 더 짧아지는 쪽으로만 고친다. §2의 원인 → 원칙 표가 이 시스템의 테스트 스위트다. 이번에는 실패도 `pipeline.jsonl`과 `usage.jsonl`에 데이터로 남는다.
