### yc-lecture에서 살릴 것과 버릴 것

**살린다**
- 출처 추적: 인용 칩에서 전사 시각으로 바로 가는 흐름.
- 사실과 해석의 분리(🔥/📘/★/📋 → 이번에는 정한 것/할 것/기다리는 것/미정).
- 모르는 것을 지우지 않고 남기기(❓ 보존).
- 원본 보존.
- 별칭으로 부르기.
- append-only 로그.
- `tools/transcribe.sh`의 환각 방지 옵션과 "고유 문장 20% 미만이면 실패" 자체 점검. 실측(39분 강의에서 같은 문장 2,983회 반복)으로 검증된 노하우다.

**버린다**

- 과목 격리를 저장 구조의 벽으로 둔 것.
- `claude -p` 브리지.
- 서버와 브라우저로 실행하는 방식.

## 3. 시스템 개요

```
 [폰]                                   [맥: Mulgil.app — 메뉴바 상주, 단일 프로세스, 서버 없음]
 iPhone 음성메모 ──iCloud──┐
 (또는 Just Press Record)   │  FSEvents       ┌──────────────────────────────────────────────┐
 Galaxy 녹음 ──Syncthing────┼───────────────▶│ Ingest → Normalize → VAD → Transcribe → Gate │
 Zoom/화면녹화/다운로드 ────┘                 │      ↓ sha·creation_time                     │
                                              │ Matcher(시간 겹침·시리즈) → L1 규칙 후보      │
 폰 캘린더 "물길 수신함" ─┐                   │ KoreanDateParser · QuickCapture(단축키)       │
 원본 캘린더(iCloud/Google)┼─EventKit 읽기──▶│ Store: SQLite(GRDB) + derived/*.md            │
                          │                   │ HealthMonitor(경로 생존 신호)                 │
 repo_paths(0~3) git log ─┘                   └───────┬───────────────┬──────────────────────┘
                                                      │               │
                          맥 표면 3개: ① 팝오버 "지금"  ② T-10/마무리 카드  ③ 빠른 캡처
                                                      │
                          EventKit 쓰기 ──▶ "물길" 섀도 캘린더 ──동기화──▶ 폰 캘린더 앱
                                        ──▶ Reminders "물길"(iPhone) ◀── 완료 플래그만 회수
```

- 사람이 해야 하는 일은 다음 넷뿐이다. 녹음 버튼 누르기, 회의가 끝날 때 한 줄 적기(또는 녹음 끝에 말하기), 카톡 문장을 복사해서 단축키 누르기, 가끔 "맞아요/아니에요" 고르기.
- 폰 앱은 v1에 없다. 폰에서는 입력이 OS 녹음 앱과 수신함 캘린더로, 출력이 섀도 캘린더와 Reminders로 이루어진다.

## 4. 데이터 모델

```
 Series ─1:N─ Event ◀── Link(method, score) ── Capture ─1:1─ Transcript ─1:N─ Segment[t0,t1,text]
   │ project(처음 쓰일 때 1회)  │ 1:N                 │ 0..1 근거(t초)
   ▼                            ▼                     ▼
 Project ◀──────────── Mark { owe | wait | decision | question }
```

| 객체 | 핵심 필드 | 규칙 |
|---|---|---|
| **Event** | `key = calendarItemExternalIdentifier + occurrenceDate`, series_id, kind(meeting/class/deadline/exam/adhoc), closed_state(none/marked/nothing) | 미러와 오버레이만 둔다. 제목과 시각은 항상 EventKit에서 읽는다. 반복 일정에서는 eventIdentifier가 불안정하므로 이 키를 쓴다. **원본 이벤트에는 절대 쓰지 않는다**(공유 이벤트면 동아리원 전원에게 노출되기 때문) |
| **Series** | 제목 정규화 + 반복 규칙 + 캘린더 출처, project_id?, glossary[], recordable(bool) | 자동으로 생성된다. 일괄 지정 시트는 없다. 그 시리즈 카드가 처음 뜰 때 칩으로 "AUSG 맞죠?"를 한 번 묻는다【레드팀: UX fatal】. `recordable`은 강의 녹음 허락 여부다(§5.9) |
| **Project** | name, aliases[], color(한번 정하면 영구 고정), repo_paths[0~3], cloud_stt_allowed=false | 폴더가 아니라 렌즈다. 이번 주에 활동이 있는 프로젝트만 색을 쓰고 나머지는 회색으로 둔다. 21일 동안 활동이 없으면 접힌다. 색은 반납하지 않는다【레드팀: UX minor】 |
| **Capture** | sha256, kind(audio/video/doc/paste), origin_path, local_copy_path?, recorded_at, duration, level(L0/L1), quality(ok/warn/fail) | 원본은 옮기지 않는다. 이벤트 없이도 존재할 수 있다(화면 표기 "일정 없음") |
| **Transcript/Segment** | engine, 품질 지표, [t0,t1,text] | 파생물이다. 원본과 엔진만 있으면 다시 만들 수 있다 |
| **Mark** | kind, text, due(date/datetime/없음), state(candidate/open/done/dropped), origin(closing-card / voice-keyword / paste / inbox / transcript-rule / github), event_key?, capture_id?, t?, reminder_id? | **불변식: Mark = 무엇 + 기한(선택).** 우선순위, 하위 작업, 담당자 필드는 영구 금지. candidate는 사람이 확정하기 전까지 어디에도 쓰지 않는다 |
| **Link** | capture↔event, method(time-overlap/manual/backfill), score | 자동으로 만든 연결은 모두 근거를 남기고, 1탭으로 해제할 수 있다 |

**의도적으로 두지 않는 것**: 지식그래프, Person 객체, 태그 체계, 폴더 트리, 자체 일정 DB, 자체 할 일 앱.

### 5.1 녹음 공통 파이프라인 (맥)

```
[감지]   FSEvents(감시 폴더), 확장자 .m4a/.qta/.caf/.mp4/.mov
[안정화] 30초간 크기 불변 · iCloud placeholder면 startDownloadingUbiquitousItem (미확인: 실측 필요)
[정규화] AVAsset으로 열기 → 실패하면 ffmpeg로 오디오 추출 → 16kHz mono wav(임시)
[중복]   sha256. 모든 단계가 멱등이라 다시 돌려도 안전
[시각]   AVAsset creationDate > 파일명 타임스탬프 > mtime
[보관]   ~/Mulgil/audio/<sha>.m4a  AAC 64kbps mono(1시간 ≈ 28MB). 원본은 참조만
[매칭]   §5.4 → Series/Project → initial_prompt = 프로젝트명+별칭+시리즈 용어집(문자열 조립)
[VAD]    silero-vad(또는 FluidAudio VAD)로 음성 구간만 청크로 자름 ← Whisper 환각의 주원인인 무음·배경음 제거
[전사]   D1에서 이긴 엔진. mlx-whisper라면 transcribe.sh 옵션 그대로:
         --condition-on-previous-text False --compression-ratio-threshold 2.0
         --hallucination-silence-threshold 2 --temperature 0 --initial-prompt …
         전원 연결 시 즉시, 배터리 상태에서는 60분 이상 녹음을 전원 연결까지 대기
[게이트] 고유 문장 < 20% → fail · 반복 n-gram 비율 · 음성 구간 대비 글자 수
         fail → 청크를 더 작게 나눠 1회 재시도 → 그래도 fail이면 quality=fail("녹음만 있어요"로 표시)
[L1]     §5.8 규칙 후보(이벤트 종류별)
[기록]   derived/<sha>/transcript.{json,md}, SQLite, log/pipeline.jsonl(append-only)
```

- 처리가 끝나도 알림을 보내지 않는다. 결과는 다음 T-10 카드와 팝오버에 나타난다【레드팀: UX major, 알림 과다】.
- 클라우드 STT는 기본으로 꺼 둔다. 해당 프로젝트에서 `cloud_stt_allowed`를 켰고 로컬에서 2회 실패했을 때만 쓴다. 옵트인 화면에 "다른 사람의 발화가 외부 서버로 전송됨"을 적는다.
- 원본이 iCloud에만 있으면 안 된다. 용량이 차면 업로드가 멈추고, 음성 메모에서 지운 녹음은 30일 뒤 사라지기 때문이다. 그래서 로컬 압축본을 기본으로 둔다【레드팀: 현실성 major】.

### 5.4 녹음 ↔ 이벤트 매칭 (결정론)

```
R = [recorded_at, recorded_at + duration]; 종일 일정과 '무시' 캘린더는 제외
후보 E: R과 겹치거나 시작 시각이 ±15분 이내
score = 0.7·|R∩E|/min(|R|,|E|) + 0.15·(같은 시리즈 최근 녹음 이력) + 0.15·(캘린더 출처 일치)
score ≥ 0.6 이고 1·2위 차 ≥ 0.2 → 조용히 연결(카드에 "다른 일정이었어요?" 링크)
애매함   → 팝오버 "확인할 것"에 후보 2~3개 + [일정 없음] + [이 시각에 회의 있었음]
겹침 없음 → 기본값 [일정 없음]. 소급 이벤트는 제안만 하고 캘린더를 오염시키지 않음
```

- 매칭률은 캘린더가 실제와 얼마나 맞는지에 달려 있다. 그래서 §5.0의 0번 감사와 §5.7의 카톡 캡처가 녹음 파이프라인의 전제 조건이다.
- 1~2단계 기간에는 팝오버 하단에 "어제 일정 매칭 2/3"을 한 줄로 보여 준다(보정 기간, 이후 숨김)【레드팀: 생존 fatal】.

### 5.5 캘린더

- 맥 시스템 설정 → 인터넷 계정에 Google을 추가하면 EventKit으로 읽고 쓸 수 있다. Google OAuth 테스트 앱은 refresh token이 7일 만에 만료되는 함정이 있어 피한다.
- `requestFullAccessToEvents`를 쓴다. 권한 요청이 조용히 false를 반환하는 사례가 있으니 authorizationStatus를 먼저 확인한다.
- Google 소스는 푸시가 아니라 맥 캘린더의 새로 고침 주기에 따라 반영된다. 그래서 다음처럼 대응한다【레드팀: 현실성 minor】.
  - 온보딩에서 캘린더 앱의 Google 새로 고침 주기를 "1분" 또는 "자동"으로 바꾸게 안내한다.
  - `EKEventStoreChanged`가 올 때마다, 그리고 30분마다 "앞으로 2시간" 안의 일정에 대해 섀도를 다시 계산한다.
  - 시작 20분 이내에 처음 발견한 회의는 맥 카드만 띄우고 섀도 쓰기는 생략한다.

### 5.7 약속 캡처: 입력이 0이 될 수 없는 곳

**사실 정리**【레드팀: 현실성 major】
- 카톡 대화는 읽을 수 없다. 카카오 메시지 API는 보내기 전용이다.
- 톡캘린더는 **본인 사용자 캘린더**의 일정 조회·생성 REST API(`kapi.kakao.com/v2/api/calendar/...`)가 있다는 정보가 있다. 다만 원문은 직접 열람하지 못했다(미확인). 채팅방 공유 캘린더 API는 미지원이다.
- 그래서 카톡 경로는 사람이 넘겨주는 수동 경로이고, 이 경로를 최고로 매끄럽게 만드는 것이 승부처다.

**맥: 빠른 캡처**
- 카톡 문장을 복사하고 단축키를 누른다. 기본값은 ⌃⌥Space이고, 온보딩에서 충돌을 검사한 뒤 녹화로 고른다.
  - 단축키는 Carbon `RegisterEventHotKey`로 등록해 접근성 권한을 받지 않는다.
- 클립보드 내용이 미리 채워진다. 로컬 규칙 파서가 기준 시각을 "붙여넣은 시각"으로 잡고 다음 표현을 해석한다: 내일, 모레, 다음 주 X요일, 수욜/목욜, N시 반, 저녁=19시. NSDataDetector는 보조로만 쓴다.
- 프로젝트 칩은 최근 3개만 보이고, 별칭이 일치하면 하나를 미리 골라 둔다. Enter 한 번으로 끝난다.
- 한국어 IME 조합 중 Enter는 확정으로 처리하지 않는다(`markedText` 확인).
- 실제 카톡 문장 50개와 IME 시나리오로 회귀 테스트 세트를 만든다.
- "놓침: …"으로 시작하는 입력은 놓친 일정/약속으로 기록된다(성공 지표 5번).

**폰: 수신함 (앱 없음)**
- iPhone: 공유 시트 → 단축어 "물길에 넣기"를 기본 경로로 둔다. 단축어가 "물길 수신함" 캘린더에 원문을 제목으로 하는 이벤트를 만든다. 카톡이 평문을 넘기는지는 미확인이다.
- Galaxy: 제목이 `#`으로 시작하는 이벤트는 어느 캘린더에 있든 수신함 항목으로 취급한다. 기본 캘린더를 바꾸는 탭이 줄어든다. 확정하면 원문 이벤트는 지운다.
- 맥이 파싱해서 팝오버의 "확인할 것"에 올리고, 확정하면 정식 이벤트나 Mark로 옮긴다.

**회의 마무리: 맥이 없을 때도 되게**【레드팀: 생존 fatal】
1. 맥 앞에 있으면 T-10 카드가 회의 종료 시 마무리 모드로 뒤집힌다(§7).
2. 녹음 중이면 멈추기 전에 이렇게 말한다. "물길, 내가 할 것: 연사 리스트 금요일까지."
   - 파이프라인이 마지막 90초에서 호출어를 퍼지 매칭(물길/물 길)으로 찾는다.
   - 그 구간을 규칙으로 잘라 `origin=voice-keyword`인 **확정 Mark**(t 포함)로 저장한다.
   - 사람의 발화가 곧 확정이므로 candidate가 아니다. 팝오버에서 "되돌리기"만 할 수 있다.
   - 호출어 인식률은 미검증이다. 3단계에서 10회 발화로 측정하고, 인식률이 80% 미만이면 "이거 맞아요?" 후보로 내린다.
3. 녹음도 맥도 없으면 폰 수신함에 한 줄로 남긴다.

**지난 약속의 완료 처리**: 마무리 카드가 아니라 다음 T-10 카드에서 "이거 했어요?"로 묻는다【레드팀: UX major】.

### 5.8 L1 규칙 후보: 이벤트 종류별로 범위 제한

【레드팀: 생존 major】

| 이벤트 kind | 뽑는 것 | 규칙 |
|---|---|---|
| class | deadline만 | "과제/제출/시험/퀴즈/마감/발표" 키워드와 날짜 표현이 같은 문장 또는 ±1문장에 있을 때. owe/wait는 끈다(교수의 "제가 다음 주에 보여 줄게요" 같은 오탐을 막기 위해) |
| meeting | owe, deadline | 1인칭("제가/내가 ~할게요/하겠습니다")과 날짜가 **같은 문장**에 있을 때. v1에는 화자 분리가 없다 |
| 그 외 | 없음 | — |

- 목표 정밀도(후보 확정률)는 ≥ 50%다. 실제 전사본 20개로 측정한 뒤 확정한다.
- 미달이면 규칙을 **줄인다.** 늘리지 않는다.
- 후보는 회색 "이거 맞아요?"로만 존재하고, 72시간 뒤 접힌다.

### 5.9 녹음 정책 (법과 윤리)

【레드팀: 현실성 minor를 원칙으로 승격】
- 통신비밀보호법상 내가 참여한 대화를 녹음하는 것은 처벌 대상이 아니라는 것이 판례 입장이다. 내가 참여하지 않은 대화를 녹음하는 것은 불법이다. 당사자 녹음에도 동의를 요구하는 개정 논의가 있었으므로 시행 전에 다시 확인한다(미확인).
- 원칙:
  1. 내가 자리를 비운 구간은 녹음하지 않는다.
  2. 다른 사람이 있는 회의에서는 녹음 사실을 알린다.
  3. 강의는 교수 허락을 받은 과목만 `Series.recordable=true`로 둔다. 저작물이므로 사적 이용 범위에서만 쓴다.
  4. 전사와 원본을 공유하거나 내보내는 기능은 두지 않는다.

### 6.1 표면은 맥 3개, 폰 1개

【레드팀: UX fatal, 14개 접점 문제】

| 표면 | 답하는 질문 | 흡수한 것 |
|---|---|---|
| ① 메뉴바 팝오버 "지금" | 지금과 다음은? | Today, 검색(⌘F), "확인할 것"(구 저녁 정리), 아침 상태, 복귀 화면, 일요일 숫자 |
| ② T-10 카드(→ 마무리 모드로 뒤집힘) | 들어가기 전에 뭘 알아야 하지? / 방금 뭘 정했지? | 맥락 카드, 마무리 카드, 지난 약속 확인 |
| ③ 빠른 캡처 | 방금 정한 걸 어디에 두지? | 카톡 붙여넣기, 놓침 기록 |

### 6.2 하루 리듬

| 시점 | 무엇이 | 어디에 |
|---|---|---|
| 아침(팝오버를 처음 열 때) | 오늘 일정과 오늘·내일 마감, 어제 마무리 안 된 회의 수. 알림이 아니라 그날 첫 화면 상태다 | 팝오버 |
| 회의 T-10 | 지난 회차의 정한 것·미정, 내 약속("이거 했어요?"), 기다리는 것, 녹음 링크, 자료, 커밋. 일회성 이벤트에는 **자료 카드**(이벤트 notes 링크, ±2h 파일, 붙여넣은 원문)를 띄운다【레드팀: 생존 major】 | 맥 카드 + 폰 맥락 이벤트 |

| 공백 뒤 복귀 | "녹음 11개 처리됨 · 열린 약속 4 · 지난 후보 6은 접어 둠" 1회 | 팝오버 |

**알림 예산**【레드팀: UX major】
- 고정 알림은 0개다.
- 알림을 보내는 경우는 네 가지뿐이다: T-10(맥락이 있을 때), 저녁(3개 이상일 때), 경로 고장, Galaxy의 확정 약속 기한.
- 하루 상한은 4개다. 넘으면 저녁으로 미룬다.
- 시스템이 몰래 끄는 대신, 카드 안에 "이 회의 카드 그만 보기" 1탭을 둔다.

### 6.3 섀도 캘린더 규칙

【레드팀: 생존 major·현실성 major】
- iPhone이면 iCloud에 "물길" 캘린더를 EventKit으로 만든다.
- Google이면 웹에서 "물길"과 "물길 수신함" 보조 캘린더를 **손으로** 만들고, 기본 알림을 "없음"으로 둔다. Google CalDAV는 MKCALENDAR를 지원하지 않는다. 앱은 이름으로 찾아 바인딩만 한다. Android 캘린더 앱에서 동기화와 표시를 켜는 것까지 온보딩 체크리스트에 넣는다.
- 맥락 이벤트는 "지난 회차 녹음이나 열린 Mark가 있는 시리즈" 또는 "자료가 있는 일회성 이벤트"에만, 회의당 1개 만든다. 원본 시작 10분 전부터 10분짜리다.
- 쓰는 시점: 전날 23:00과 당일 07:30에 미리 쓰고, 이후 `EKEventStoreChanged`와 30분 주기로 다시 계산해 원본 시각에 맞춰 옮기거나 지운다. 섀도 notes에는 원본 키를 저장한다.
- **알람은 기본으로 넣지 않는다.** 폰 알림은 원본 알람이 맡는다. 원본 알림을 눌러 캘린더를 열면 바로 위에 맥락 이벤트가 보인다. 맥이 덮인 동안 원본이 바뀌면 섀도가 낡을 수 있으니, 낡은 이벤트에 알람이 울리는 것을 막기 위해서다. 메모 첫 줄에 `기준 07:30 · 원본 일정 확인`을 넣는다.
- 예외(Galaxy): datetime 기한이 있는 확정 owe에 한해 "기한 1시간 전" 알람 이벤트를 만든다. 같은 날 3개를 넘으면 하나로 합친다.
- Reminders(iPhone): 확정 owe를 "물길" 목록에 쓴다. **완료 플래그만 읽어 온다.** `EKReminder.isCompleted`가 true면 Mark를 done으로 바꾸고 로그에 남긴다. 제목·기한을 고친 내용은 회수하지 않는다. 이렇게 해서 이미 끝낸 일이 T-10 카드에서 미완으로 경고되는 일을 막는다.

### 6.4 겹치는 회의와 연속 회의

- 앞 회의의 마무리 모드와 다음 회의의 T-10이 겹치면 카드 하나에 두 영역을 위아래로 둔다. 위가 마무리, 아래가 다음 회의다. 마무리는 [나중에] 없이도 접히면 "확인할 것"으로 넘어간다.
- 동시에 겹친 두 이벤트는 녹음 매칭 점수로만 정한다. 카드는 내가 수락한(참석 상태 accepted) 이벤트를 우선한다.

## 7. UI/UX

### 7.1 원칙

1. **시간이 레이아웃이다.** 세로축은 항상 시각이다. 폴더, 트리, 그래프 뷰는 없다.
2. **카드 하나에 질문 하나.** 표면은 3개뿐이다(§6.1).
3. **정상일 때는 침묵한다.** 파이프라인 상태는 고장일 때만 문장 한 줄로 보여 준다. 메뉴바 아이콘은 평소 단색이고, 고장일 때 **모양**이 바뀐다(색이 아니라). 노란 상태, 빨간 배지, 미처리 카운터, "2/4" 같은 진행 표시는 없다【레드팀: UX major】.
4. **색은 프로젝트에만 쓴다.** 크롬은 시스템 머티리얼과 무채색이다. 프로젝트 색은 3px 막대와 칩에만 쓰고, 강조색은 1개(기한 임박)다.
5. **원본까지 한 번에.** 모든 문장 옆에 타임코드 칩 `‹23:41›`을 두고, 누르면 5초 전부터 재생한다.
6. **확정과 후보를 구분한다.** 내가 적은 것은 진한 본문체, 자동 후보는 회색 + "이거 맞아요?"로 쓴다. 미정은 지우지 않는다.
7. **빈 화면이 가장 아름다워야 한다.** "오늘 열린 약속 없음"은 여백에 문장 하나로 보여 준다.

### 7.2 디자인 토큰

- **기호 사전(이 4개 외에는 코드 리뷰에서 거부)**: 녹음 `waveform`(ASCII ◉), 자료 `doc`(▤), 약속 `circle`/`checkmark.circle`(○/●), 기한 `flag`(⚑). UI에 이모지는 금지한다. ❓ 대신 텍스트 "미정"을 쓴다【레드팀: UX major】.
- **타이포**: SF Pro + Apple SD Gothic Neo. 크기는 28/17/13/11 네 단계. 시각은 tabular 숫자, 타임코드는 SF Mono.
- **간격**: 4/8/12/16/24.
- **모션**: 2개뿐이다. 카드가 메뉴바에서 내려오는 것(220ms ease-out)과 확정 체크(150ms). 사운드는 없다.
- **색**: 프로젝트 8색. 한번 배정하면 영구 고정하고, 이번 주 비활성 프로젝트는 회색으로 둔다. 같은 화면에 같은 색이 두 번 나오면 칩에 이니셜을 함께 쓴다.

### 7.3 UX 라이팅 표 (화면에 내부 용어를 쓰지 않는다)

【레드팀: UX major】 레포에 `copy.md`로 두고, 문구 변경도 리뷰한다.

| 내부 | 화면 |
|---|---|
| candidate / 후보 | 이거 맞아요? |
| owe | 할 것 |
| wait | 기다리는 것 |
| decision | 정한 것 |
| question / ❓ | 미정 |
| 개인 메모(이벤트 없음) | 일정 없음 |
| 즉석 회의 소급 | 이 시각에 회의 있었음 |
| L2 노트 | 시험 정리본 만들기 |
| closed_state=nothing | 없었음 |
| Series, 렌즈, Mark, L0/L1 | 화면에 나오지 않음 |

버튼은 동사 2~4자로 쓴다: 저장, 맞아요, 아니에요, 되돌리기, 그만 보기.

### 7.4 첫 실행: 5분 안에 보상

【레드팀: UX fatal·생존 major】

```
┌ 물길 ───────────────────────────────────────────┐
│                                                 │
│  일정을 읽어도 될까요?                           │
│  다음 회의 전에 지난 맥락을 꺼내 드리려면 필요해요. │
│                                     [허용]       │
└─────────────────────────────────────────────────┘
        ↓ (캘린더 권한 하나만 먼저 받는다)
┌─────────────────────────────────────────────────┐
│  지난 4주 일정 61개를 읽었어요.                   │
│  반복 모임 9개를 찾았어요.                        │
│                                                 │
│  폰 녹음도 이어 볼까요?                           │
│  지난 녹음을 각 일정에 붙여 두면, 오늘 16:00       │
│  AUSG 운영 회의부터 지난 회차를 바로 볼 수 있어요.  │
│                [나중에]      [녹음 연결하기]       │
└─────────────────────────────────────────────────┘
        ↓ (여기서 처음 전체 디스크 접근을 요청 → 메타데이터만 읽어 시간 매칭. 전사는 3단계부터)
┌─────────────────────────────────────────────────┐
│  녹음 23개를 일정 17개에 붙였어요.                │
│  오늘 16:00 AUSG 운영 회의 — 지난 회차 11/16 · 52분 │
│                                       [좋아요]   │
└─────────────────────────────────────────────────┘
```

- 권한은 필요한 순간에 요청한다. 순서는 캘린더 → (녹음 연결 시) 전체 디스크 접근 → (첫 카드를 띄울 때) 알림 → (첫 owe 확정 시) 리마인더. 접근성 권한은 요청하지 않는다.
- 시리즈 → 프로젝트 지정 시트는 없다. 그 시리즈 카드가 처음 뜰 때 칩으로 "AUSG 맞죠? [맞아요] [다른 것]"을 묻는다.

### 7.5 화면 ①: 메뉴바 팝오버 "지금" (360pt)

【레드팀: UX minor, 히어로 1개 + 최대 3줄】

```
┌──────────────────────────────────────────────┐
│  23분 후                                      │  28pt
│ ▍AUSG 운영 회의 · 16:00 · 공학관 304           │
│ ▍ 할 것 2 (1 남음) · 기다리는 것 1      열기 ›  │
│ ──────────────────────────────────────────── │
│ ▍19:30 LikeLion 해커톤 싱크                    │
│ ▍23:59 ⚑ ERPsim 보고서                        │
│ ▍내일 09:00 자바프로그래밍                      │
│ ──────────────────────────────────────────── │
│  확인할 것 3                               ›   │  ← 있을 때만
└──────────────────────────────────────────────┘
```

- 아무것도 없는 날: 큰 여백에 "오늘 남은 일정 없음" 한 문장과, 그 아래 작게 "⌃⌥Space로 방금 정한 일정 넣기"를 둔다(빈 상태에서만).
- ⌘F는 전사, Mark, 이벤트 제목을 검색하고 결과를 "일정 · 시각" 단위로 묶는다(3단계 이후).
- 고장일 때는 맨 위에 한 줄이 생긴다. 예: "음성 메모를 읽을 수 없어요 · 권한 다시 켜기 ›"

### 7.6 화면 ②-a: T-10 카드 (회의 전)

```
┌─ AUSG 운영 회의 · 10분 후 · 공학관 304 ─────────────────┐
│ 지난 회차 11/16 · ◉ 52분                                │
│  정한 것  12월 밋업 장소 = 판교                  ‹23:41› │
│  정한 것  연사 2명 섭외                          ‹31:05› │
│  미정     예산 승인 주체                         ‹40:12› │
│ 할 것   연사 리스트 공유 · 오늘 ⚑    [했어요] [아직]       │
│ 기다리는 것  예산안 ← 민지                               │
│ ▤ 밋업기획.pptx  ▤ 예산.xlsx  · ausg-web 커밋 3          │
│                               [그만 보기]   [열기]       │
└──────────────────────────────────────────────────────────┘
```

- nonactivating `NSPanel`이라 포커스를 빼앗지 않는다. 회의 시작 5분 뒤 자동으로 축소된다.
- **화면 공유나 발표 중에는 절대 띄우지 않는다.** 대신 메뉴바 아이콘에 점만 찍는다【레드팀: UX major】.
  - 감지 대상: Keynote/PowerPoint 프레젠테이션 모드(전체 화면 창 소유자 확인), Zoom/Meet 화면 공유 창(CGWindowList 창 이름 휴리스틱, 미확인), macOS 집중 모드(감지 API는 미확인).
  - 감지에 실패할 때에 대비해, 외부 디스플레이가 미러링 중이면 카드를 띄우지 않는 규칙도 함께 둔다.
- LLM을 꺼도 이 카드는 완전하다. 확정 Mark, 녹음 링크, 파일, 커밋이 모두 결정론적으로 나온다.

### 7.7 화면 ②-b: 같은 카드, 마무리 모드 (회의 종료)

【레드팀: UX major, 입력칸 1 + 버튼 2】

```
┌─ AUSG 운영 회의 끝 ─────────────────────────────┐
│ 방금 정한 것 · 약속                              │
│ [ 연사 리스트 금요일까지 공유할게          ]      │
│   → 할 것 · 금 11/27                (회색 추론)  │
│                         [없었음]      [⏎]       │
└─────────────────────────────────────────────────┘
```

- 파서가 종류를 추론한다: "~할게"는 할 것, "~받기로"와 "← 이름"은 기다리는 것, "?"는 미정, 그 밖은 정한 것. 틀리면 추론 칩을 눌러 바꾼다.
- 문장에 날짜가 없을 때만 [목][금][다음 주] 칩이 나타난다.
- 여러 줄은 Enter로 이어서 쓴다. [없었음]을 누르면 "약속 0"이 명시적으로 기록된다.

## 8. AI의 역할 경계

| AI(모델)가 하는 것: 보이지 않는 배관 | 방식 |
|---|---|
| 음성 → 텍스트 | 로컬 mlx-whisper 또는 SpeechTranscriber(D1 승자 1개) + VAD |
| (v2) 화자 분리 | FluidAudio(Swift/CoreML, 오프라인). 이름 후보는 이벤트 참석자 |

| 규칙(비AI)이 하는 것 |
|---|
| 녹음-이벤트 매칭, 시리즈 → 프로젝트 상속, 한국어 날짜 파싱, Mark 종류 추론, L1 후보 추출, 호출어 구간 자르기, initial_prompt 조립, 접기와 만료, 알림 시점, 지표 집계. 모두 단위 테스트와 회귀 세트로 검증한다 |

**절대 하지 않는 것**
1. 내가 확정하지 않은 것을 캘린더, 리마인더, 섀도 캘린더에 쓰기.
2. 요약 산문을 주인공으로 두기. 카드의 주인공은 내가 적은 정한 것·할 것과 원본 타임코드다.
3. 출처(타임코드, 파일) 없이 말하기.
4. 프로젝트를 만들거나 바꾸거나 판단하기.
5. 핵심 루프에 들어가기. LLM off 스위치가 있고, 꺼도 100% 동작한다. 채팅 창과 `claude -p` 브리지는 없다.
6. 기본 설정으로 타인의 발화를 외부에 보내기.
7. 파일 이름을 바꾸거나, 옮기거나, 지우기.

**L2(시험 정리본)와 Claude Code**: 시험 이벤트(kind=exam)가 있을 때만 이벤트 상세에 [시험 정리본 만들기]가 생긴다. 이 버튼은 고른 주차의 `transcript.md` 경로 목록과 `/home/user/yc-lecture/CLAUDE.md` 노트 규칙 경로를 `~/Mulgil/export/l2-request.md`로 내보낼 뿐이다. 노트 작성은 제품 밖에서 Claude Code로 한다. 제품은 Claude에 의존하지 않는다.

## 9. 기술 아키텍처와 스택

| 영역 | 선택 |
|---|---|
| 앱 | Swift 6 / SwiftUI, macOS 26, `LSUIElement` 메뉴바, `SMAppService` 로그인 항목, 단일 프로세스. 서버·브라우저·포트 없음 |
| 저장 | SQLite(GRDB) + FTS5(3단계), `derived/` 파일 |
| 캘린더/리마인더 | EventKit (`requestFullAccessToEvents`/`Reminders`) |
| 파일 감지 | FSEvents |
| 오디오 | AVFoundation, ffmpeg(정규화), silero-vad 또는 FluidAudio VAD |
| 전사 | SpeechTranscriber 또는 mlx-whisper(고정 버전 `engine/.venv`, `Process`로 호출) |
| 단축키 | Carbon `RegisterEventHotKey` |
| 카드 | nonactivating `NSPanel` |
| 알림 | UserNotifications |
| Galaxy 푸시 대체 | ntfy (D1 3번이 실패할 때만) |

**저장 구조**
```
~/Mulgil/
  mulgil.sqlite                  # 오버레이, Series, Project, Capture, Mark, Link
  audio/<sha>.m4a                # 로컬 압축 보관본(64kbps mono)
  derived/<sha>/transcript.json  # 세그먼트, 엔진, 품질 지표
  derived/<sha>/transcript.md    # 헤더에 출처/이벤트/엔진. grep 가능
  inbox/                         # 수동 투입(밀린 녹음 등) — Galaxy는 inbox/phone/
  log/pipeline.jsonl             # append-only 처리 이력
  log/usage.jsonl                # 카드 열람·확정·무시 (지표용)
  export/                        # 매일 밤 marks.jsonl + SQLite 백업 30일
```
- SQLite가 깨져도 `derived/`와 원본에서 재구축할 수 있다.
- transcript와 derived는 git에 넣지 않는다. 커밋 수가 작업량처럼 보이는 보상 루프를 끊기 위해서다.

**서명과 권한**【레드팀: 현실성 minor】
- 항상 같은 Apple Development 인증서(Personal Team도 가능)로 서명하고, 번들 ID를 고정한다. 그래야 다시 빌드해도 TCC 권한이 풀리지 않는다.
- 샌드박스는 끄고, 파일은 경로와 sha로만 참조한다.
- 앱 시작 시와 macOS 업데이트 후 첫 실행 시 권한을 자가 점검한다.

**HealthMonitor: 경로 생존 신호**【레드팀: 생존 major】

| 구분 | 점검 내용 |
|---|---|
| 빨강(알림) | 음성 메모 컨테이너 읽기 실패 · Syncthing REST API로 본 폰 lastSeen > 24h · iCloud 남은 공간 < 500MB · ko 에셋 소실 · 원본 경로 소실. 매시간 점검 |
| 정보(알림 없음, 팝오버 첫 화면 한 줄) | "어제 끝난 수업·회의 3개 · 녹음 0" |
| 보조 | iPhone 경로에서 음성 메모 DB(`CloudRecordings.db`) mtime이 오래 멈춰 있으면 정보성 표시(미확인) |

녹음 수가 0인 것만으로는 빨간불을 켜지 않는다. 그냥 녹음을 안 한 날과 고장을 구분할 수 없어서, 오경보가 쌓이면 진짜 고장까지 무시하게 되기 때문이다.

**철수 경로**【레드팀: 생존 missing】
- 메뉴 → "물길 그만 쓰기"는 다음을 한다: 섀도·수신함 캘린더와 Reminders "물길" 목록 삭제(Google 보조 캘린더는 삭제 방법 안내), marks.jsonl과 transcript.md 내보내기, 로그인 항목 해제.
- 원본 녹음은 건드리지 않는다.

5. "놓침:" 기록이 주 0~1건.
6. L1 후보 확정률 ≥ 50%.
7. 하루 이상 쉬었다 돌아왔을 때 할 일 0.

## 11. 사망 시나리오와 안전장치

| 사인 | 조기 신호 | 안전장치 |
|---|---|---|
| ① **캘린더가 실제와 달라 뼈대가 빈다** | D0 감사에서 70% 미만, 매칭 "겹침 없음" > 30% | 1단계 첫 작업을 카톡 → 일정 2탭으로 바꾼다. 해커톤은 기간 전체를 종일 이벤트로 감싼다. 매칭률을 1~2단계 동안 매일 보여 준다 |
| ② **기말과 방학이 측정을 오염시킨다** | 사용량 급감의 원인을 가를 수 없음 | 기말에는 코드 금지, 방학 분모를 미리 넣기, 최종 판정은 3월 개강 3주차 |
| ③ **맥이 없는 곳에서 회의가 끝난다** | 마무리 건너뛰기 > 80% | 녹음 끝 호출어, 폰 수신함. "확인할 것"은 되돌리기 위주. 카드는 **더 줄이는 방향으로만** 고친다 |
| ④ **한 방향 쓰기로 신뢰가 깨진다** | 이미 끝낸 일이 미완으로 경고됨, 낡은 섀도 | Reminders 완료 회수, 섀도 재배치와 기본 알람 없음, "기준 시각" 표시 |
| ⑤ **push가 닿지 않는다** | 맥락 카드를 본 비율 < 30% | 시리즈별로 본 비율을 집계한다. iOS 위젯과 ntfy를 v2 첫 순위로 |
| ⑥ **무인 파이프라인이 조용히 멈춘다** (TCC 상실, 음성 메모 앱이 꺼져 동기화 안 됨, Syncthing 종료, iCloud 용량) | 경로 생존 신호 실패 | HealthMonitor(§9), 30분 주기 `open -gj`, 고정 인증서, 업데이트 후 자가 점검, 대체 경로 문서화(Just Press Record, FolderSync) |
| ⑦ **후보 홍수로 후보를 무시하는 습관이 생긴다** | 후보 확정률 < 50% | 강의는 deadline만 뽑는다. 회의는 1인칭 + 날짜가 같은 문장일 때만. 미달이면 규칙을 줄인다 |
| ⑧ **첫 2주에 보상이 비어 있다** | 1단계 실사용 중 카드 0 | 첫 실행 백필(지난 4주 일정 + 녹음 메타데이터), 일회성 이벤트용 자료 카드 |
| ⑨ **빌더 함정이 재발한다** | 동결 중 비버그 머지 > 0 | 외부 승인자, 커밋 훅, 하루 1시간 다듬기 출구, 보상 스프린트 |
| ⑩ **"TodoList 3호"가 된다** | 캡처 1건 중앙값 > 10초, Mark 필드를 추가하고 싶어짐 | Mark 불변식을 지킨다. 장부 창은 금지. 시간 화면 안에서만 보인다 |
| ⑪ **한국어 전사 품질이 무너진다** | 품질 경고 > 15% | VAD, 용어집 initial_prompt, 프로젝트 단위 클라우드 옵트인. 경고가 뜬 녹음은 카드에 "녹음만" 표시한다. 가치의 중심이 약속과 타이밍이라 카드는 살아남는다 |
| ⑫ **녹음 자체가 줄어든다** | 주간 녹음 수 급감 | 녹음은 강화 재료일 뿐 전제가 아니다. 카드, 마무리, 수신함은 녹음 없이도 돈다 |
| ⑬ **결국 안 쓴다** | 14일 중 팝오버를 연 날 < 7 | 기능을 더하지 말고 3질문만 묻는다. (a) 녹음이 자동으로 들어왔나? (b) 카드가 회의 전에 떴나? (c) 떴는데 안 봤다면 내용이 비었나, 타이밍이 틀렸나? 답이 가리키는 한 지점만 고친다. 그래도 안 되면 철수 경로(§9)로 깨끗하게 끝낸다 |

**가장 약한 고리**는 기술이 아니라 회의 종료 직후의 한 줄이다. 그래서 설계는 두 가지를 지킨다. 첫째, 그 한 줄이 무너져도 녹음, 캘린더, 섀도 출력은 계속 돈다. 둘째, 의식은 늘 더 짧아지는 쪽으로만 고친다. §2의 원인 → 원칙 표가 이 시스템의 테스트 스위트다. 이번에는 실패도 `pipeline.jsonl`과 `usage.jsonl`에 데이터로 남는다.

4. **iCloud 플랜과 남은 용량은?** 무료 5GB인가?
5. **지난 7주 강의 녹음이 폰이나 로컬에 남아 있는가?** 남아 있다면 3단계 첫 검증 데이터가 된다.
6. **강의 녹음은 과목별로 교수 허락을 받았는가?** 동아리 회의에서 녹음을 알리는 것은 괜찮은가?

8. **맥은 낮에 주로 덮여 있는가, 들고 다니며 여는가?** 덮여 있는 시간이 길면 폰 경로(2단계)의 비중을 올린다.
9. **이미 쓰는 전역 단축키(Raycast, Alfred, ChatGPT)는?** 빠른 캡처 단축키 충돌 검사에 쓴다.

11. **빅 인벤토리 코드는 어디에 있는가?** 위치를 알려 주면 "넣는 노동, 돌려주는 순간 0" 진단이 맞는지 확인한다.
12. **iPhone이라면 iOS 26 음성 메모의 한국어 기본 전사를 실제로 쓰고 있는가?** 파일에서 꺼낼 수 있다면 STT 경로가 단순해진다(미확인).
